# 改完必须同步，否则重启也没用

一句话：**仓库不是 dsh 加载的东西。** dsh 读的是
`~/.dsh/profiles/web/node_modules/dsh-whale-memory/`，改完仓库不同步，
页面、端点、行为全都是旧的；**重启读的还是那个旧文件，所以重启不解决任何事。**

## 一条命令

```bash
node ~/.dsh/im/whale-memory/scripts/install-local.mjs
```

它做三件事，幂等，可以反复跑：

1. 把 `whale-memory` / `corpus` / `proactive` 三个包复制进 profile 的 `node_modules`；
2. 把缺的包名补进 profile `package.json` 的 `dsh.profile.bundles`；
3. 复制完**立刻逐文件比对**（`client.js`、`lib/**`、`package.json`、`cordis.patch.yml`、`README.md`），
   有不一致就列出文件名并 `exit 1`。

只校验、不动文件：

```bash
node ~/.dsh/im/whale-memory/scripts/verify-install.mjs            # 默认 profile
node ~/.dsh/im/whale-memory/scripts/verify-install.mjs --profile ~/.dsh/profiles/web
node ~/.dsh/im/whale-memory/scripts/verify-install.mjs --json     # 机器可读
```

- 副本不存在或 profile 不存在：打 `SKIP`，退出码 0（CI 上没有 profile 不算失败）。
- 不一致：打印 `文件 旧/缺：版本 A → B（仓库 mtime / 副本 mtime）`，退出码 1。

`scripts/check-all.mjs` 第二步就是它，所以 `npm run check:all` 会顺带拦住「改完没同步」。

## 事故记录（0.28.7）

- 仓库 `client.js` 加了「冷热分层」设置组，`package.json` 升到 0.28.7；
- 只改了仓库，没跑 `install-local.mjs`，副本还停在 0.28.5（`01:03` 那份）；
- 于是设置页看不到这一组，`/dsh-whale-memory/status` 报的 `pluginVersion` 还是 `0.28.5`；
- 期间重启过一次 dsh —— **没有用**，因为重启加载的仍是 `node_modules` 里的旧文件。

同一次比对还查出：`lib/tidy.mjs`（0.28.6 新增）在整个副本里缺失，
`lib/recall.mjs`、`lib/index.mjs`、`lib/shared.mjs`、`lib/constants.mjs` 也都是旧的。
也就是说 0.28.6 的记忆分层（`hits`/`tier`、层级惩罚）从来没在运行的实例里生效过。

## 哪些文件算「必须同步」

`client.js`、`cordis.patch.yml`、`package.json`、`README.md`、整个 `lib/`。
副本里多出来的文件不管（那是 npm 或别的工具留下的，不属于不同步）。

## 排查顺序

1. `curl -s http://127.0.0.1:3080/dsh-whale-memory/status | head -c 200` → 看 `pluginVersion` 对不对；
2. 不对就 `verify-install.mjs`，看是哪个文件旧；
3. `install-local.mjs` 同步；
4. 还不对才重启 dsh。

`scripts/protect.sh` 的「装回我自己的三个插件」一步现在会在装完后
再跑一次 `verify-install.mjs`，失败时把 `FAILED=1` 记下来，收尾 `exit 1`。
