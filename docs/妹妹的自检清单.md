# 给鲸鱼姬：插件目录被清掉之后怎么自愈

同一种事故发生过两次：安装别的插件时，`node_modules` 里**没在 bundles 登记的目录**会被清掉。
被清掉的是：`dsh-whale-memory`、`dsh-group-corpus`、`dsh-proactive-message`。
`bundles` 里的名字一直都在，所以现象是「插件没加载」，不是「依赖丢了」。

## 一、先确认是什么没了

在 profile 目录里跑（Windows 是 `%USERPROFILE%\.dsh\profiles\web`）：

```
ls node_modules/dsh-whale-memory node_modules/dsh-group-corpus node_modules/dsh-proactive-message
```

三个都报「找不到」就是全丢了；只缺一个就补那一个。

## 二、补回来

从你自己的仓库副本（或备份的 0.5.3 源码）整目录复制进 `node_modules`：

```
cp -a <备份>/dsh-whale-memory      <profile>/node_modules/
cp -a <备份>/corpus                <profile>/node_modules/dsh-group-corpus
cp -a <备份>/proactive             <profile>/node_modules/dsh-proactive-message
```

（Windows 用 `xcopy /E /I`。仓库里三个目录名分别是根目录、`corpus/`、`proactive/`，装进 node_modules 时要改成包名。）

补完重启 dsh，看侧边栏有没有回来。

## 三、让它别再发生

核心思路是**开机自检**：启动时检查三个目录在不在，缺哪个从备份补哪个，补完再校验。

Linux/macOS 的版本在 `scripts/protect.sh`；Windows 写一个 `protect.ps1` 放同一个位置，
用计划任务在登录时跑一次。判断逻辑就三条：

1. 三个目录存在吗？缺了就 copy。
2. copy 完 `node --check` 关键文件（`lib/index.mjs`、`corpus/index.js`、`proactive/index.js`）。
3. 失败就报警，不要静默通过——静默失败比丢失更坏。

## 四、数据别跟着丢

插件是代码，**记忆是数据**。数据放一个固定目录（我这边是 `~/.dsh/miyu/`），
代码目录随便重装都不影响数据；再加一个私有备份仓，每天推一次。
这样最坏情况是重装插件，不是失忆。
